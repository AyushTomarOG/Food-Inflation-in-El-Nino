# Food Inflation Forecasting using El Niño Indices

## Project Overview

This project focuses on **forecasting Indian food inflation using historical food inflation data and El Niño climate indicators**.

The project compares multiple time-series forecasting approaches under a **common chronological test period** and evaluates their forecasting performance using standard error metrics.

The models currently implemented are:

- **ARIMAX** — classical statistical forecasting with ONI as an exogenous variable
- **Prophet** — time-series forecasting with ONI as an additional regressor
- **LSTM + ONI** — multivariate deep-learning model using food inflation and ONI
- **LSTM Baseline** — univariate LSTM using only historical food inflation

The project also includes a **FastAPI backend** that exposes the processed data, model predictions, comparison metrics, and latest forecasts through REST APIs.

---

## Objectives

The main objectives of the project are:

1. Derive a food inflation time series from the available CPI/CFPI data.
2. Incorporate the **Oceanic Niño Index (ONI)** as a climate-related explanatory variable.
3. Implement and compare different forecasting approaches.
4. Evaluate all models on the same chronological unseen test period.
5. Compare the models using MAE, RMSE, sMAPE, and MASE.
6. Provide the forecasting results through a backend API.

---

## Models

### 1. ARIMAX

ARIMAX extends ARIMA by incorporating an external explanatory variable.

In this project:

- Target: Food Inflation
- Exogenous variable: ONI
- Test period: January 2024 – December 2025

### 2. Prophet

Prophet is used as a time-series forecasting model with ONI supplied as an additional regressor.

The model produces:

- Forecasted food inflation
- Lower prediction bound
- Upper prediction bound

### 3. LSTM + ONI

A multivariate LSTM model is used with:

- Food Inflation
- ONI

The model uses a **12-month lookback window** to create sequential training samples.

Architecture:

```text
Input Sequence
      ↓
LSTM (64 units)
      ↓
Dropout (0.2)
      ↓
Dense (32, ReLU)
      ↓
Dense (1)
      ↓
Food Inflation Forecast
```

### 4. LSTM Baseline

A baseline LSTM model is also implemented using **only historical food inflation**.

This provides a reference point to determine whether adding ONI improves forecasting performance.

Architecture and sequence setup are kept comparable to the multivariate LSTM.

## Evaluation Strategy

All models are evaluated on the same chronological unseen test period:

**January 2024 – December 2025**

A common test period is used so that the models can be compared fairly.

The following metrics are used:

### MAE

Mean Absolute Error — measures the average absolute difference between actual and predicted values.

### RMSE

Root Mean Squared Error — penalizes larger prediction errors more strongly than MAE.

### sMAPE

Symmetric Mean Absolute Percentage Error — measures forecast error relative to the magnitude of actual and predicted values.

### MASE

Mean Absolute Scaled Error — compares forecasting error against a scaled baseline based on historical changes.

For all four metrics:

> Lower values indicate better forecasting performance.

## Current Results

The current model comparison is:

| Model | MAE | RMSE | sMAPE (%) | MASE | Avg. Rank |
|---|---:|---:|---:|---:|---:|
| **LSTM Baseline** | **1.316956** | **1.658211** | **44.185169** | **0.978711** | **1.00** |
| LSTM + ONI | 4.201831 | 4.984564 | 90.559779 | 3.122639 | 2.25 |
| Prophet | 4.524748 | 5.100074 | 103.685090 | 3.362619 | 3.25 |
| ARIMAX | 5.116283 | 6.968454 | 86.691679 | 3.802225 | 3.50 |

### Current Observation

The **LSTM Baseline currently performs best across all four evaluation metrics**.

This indicates that, in the current experiment, using historical food inflation alone produced more accurate forecasts than the models that incorporated ONI.

The results are experimental and may change as the forecasting pipeline and feature engineering are further refined.

# Backend API

The project includes a **FastAPI backend** for serving the forecasting results.

The backend reads the processed CSV outputs generated by the analysis notebooks rather than hardcoding model results.

## API Endpoints

### Root

```http
GET /
```

Returns a basic API status message.

### Health Check

```http
GET /health
```

Returns the health/status of the forecasting API.

### Data

```http
GET /data
```

Returns the processed food inflation and ONI dataset.

### Predictions

```http
GET /predictions
```

Returns predictions from all available models.

Available model filters:

```http
GET /predictions?model=arimax
GET /predictions?model=prophet
GET /predictions?model=lstm_oni
GET /predictions?model=lstm_baseline
```

### Model Comparison

```http
GET /comparison
```

Returns the evaluation metrics generated by the model comparison notebook.

The endpoint reads:

```text
data/processed/model_comparison.csv
```

This keeps the API dynamically connected to the latest model-comparison results.

### Latest Forecast

```http
GET /forecast
```

Returns the latest available food-inflation forecast for each model.

### Model-Specific Forecast

```http
GET /forecast/arimax
GET /forecast/prophet
GET /forecast/lstm_oni
GET /forecast/lstm_baseline
```

Returns the latest forecast for the selected model.

FastAPI automatically provides an interactive Swagger UI for testing the endpoints.
